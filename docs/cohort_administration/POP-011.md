# POP-011 — Shared selection controls

Branch: `feat/pop-011-multi-selection`, based on Components `master` at `4f52bbef9`.

This ticket implements the shared controls used by the population editor. It does not introduce the population editor, App Backoffice orchestration, API calls or a membership engine. POP-001 contracts are documented in App Backoffice PR [#1362](https://github.com/CoorpAcademy/app-backoffice/pull/1362).

## Component contracts

### Autocomplete

Existing behaviour stays the default. The following optional props enable population-style multi-selection:

| Prop | Purpose |
|---|---|
| `id` | Stable suggestion-container identity for independent inputs |
| `aria-label` | Accessible input name |
| `disabled` | Disable the input and suggestion display |
| `showSuggestionsOnFocus` | Show available suggestions for an empty focused input |
| `keepSuggestionsOnSelect` | Keep the remaining suggestions usable after mouse or keyboard selection |
| `focusInputOnSuggestionClick` | Existing prop: retain input focus after choosing an option |

The caller controls input text, selected values, suggestion content, loading/error handling and explicit creation options. `onSuggestionSelected` receives the existing selection data object. The primitive never creates a value on blur. Escape and blur close the menu. Only transient menu visibility is owned inside the control.

### SelectMultiple

The existing single/multiple selection callbacks retain their shapes. New optional props are:

| Prop | Purpose |
|---|---|
| `aria-label` | Enables named keyboard interaction and focus management |
| `search: {value, label, emptyLabel, onChange}` | Controlled case-insensitive substring filtering by option name |
| `selectionLabel` | Caller-provided summary, such as “12 playlists selected” |
| `dropdownClassName` | Layout customisation by a consuming Components component |
| `options[].rightLabel` | String or number aligned to the right of a Coorpmanager multiple-selection option |
| `options[].warning` | Highlight a previously selected empty playlist without deleting the selection |

The complete options array remains controlled and includes selected options outside the visible search result. Filtering does not change selected values. Multiple selection leaves the menu open; single selection closes it. Arrow keys move between visible choices; Escape closes the menu and restores trigger focus. Disabling or leaving the selector closes it. Content eligibility, counts and Select all/Clear selection actions remain caller responsibilities.

### Tag

Both values and playlists reuse the existing Tag rather than separate chip implementations. The optional prop is:

```typescript
removeAction?: {
  label: string;
  onClick(): void;
  disabled?: boolean;
};
```

Use `type="info"` for blue value/catalogue tags. The action is a named `type="button"`, inherits the tag colour and never submits a surrounding form. Without `removeAction`, existing tag markup and appearance retain their behaviour. Labels for actions are supplied by the caller, so the primitive does not introduce hardcoded product translations.
